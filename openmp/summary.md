# OpenMP: краткое содержание решений

Ссылки «п. 5.x» — на разделы главы 5 «Параллельное программирование с использованием OpenMP»
(hpc-lec05-06-openmp-text.pdf). Ускорение и эффективность — по лекции 4:
`S_p = T_1 / T_p`, `E_p = S_p / p`; предел ускорения задаёт закон Амдаля `S_p ≤ 1 / (α + (1−α)/p)`,
где α — доля последовательных вычислений.

## Общее для всех задач

- **Модель fork-join** (п. 5.1–5.2): программа — чередование последовательных и параллельных
  фрагментов; `#pragma omp parallel` создаёт команду потоков, в конце фрагмента неявный барьер.
- **Распараллеливание по данным** (п. 5.3): `#pragma omp for` / `parallel for` делит итерации
  канонического цикла между потоками; итерации должны быть независимы.
- **Число потоков** (п. 5.7.5): параметр `num_threads(t)` (наивысший приоритет, выше
  `omp_set_num_threads` и `OMP_NUM_THREADS`). Серии: 1, 2, 4, 8 — меньше числа ядер,
  16 — равно числу логических CPU, 32 — больше.
- **Замер времени** (п. 5.2.5): `omp_get_wtime()`; один прогрев, затем медиана из `--reps` запусков
  ([common/bench.hpp](common/bench.hpp)). База ускорения для каждой задачи указана в [отчёте](REPORT.md).
- **Проверка**: каждый параллельный вариант сверяется с последовательным (`[FAIL]` в stderr при расхождении).
- **Почему ускорение ниже p** (лекция 4): мало работы на поток при малых N (накладные расходы на
  создание/активацию потоков больше выигрыша — п. 5.3.4), упор в пропускную способность памяти при
  больших N, синхронизация, Hyper-Threading (16 логических CPU ≠ 16 ядер), разнородные P/E-ядра.

## 1. Минимум элементов вектора

**Идея.** Каждый поток ищет минимум своей части вектора, затем частичные минимумы объединяются.

**Технологии.**
- `parallel for reduction(min : m)` (п. 5.4.2) — OpenMP сам создаёт приватные копии `m`
  (с начальным значением для операции min) и объединяет их в конце. Операции `min`/`max` в `reduction`
  появились только в OpenMP 3.1; в стандарте 2.5 из лекции их нет. Программа печатает макрос
  `_OPENMP` (п. 5.8.2): у GCC 15 это `201511` (OpenMP 4.5), поддержка есть.
- Без редукции: локальная переменная потока (объявлена внутри `parallel` ⇒ private, п. 5.4.1),
  `omp for nowait` (п. 5.3.3), затем сравнение и обновление общего минимума внутри `critical`.

## 2. Скалярное произведение

**Идея.** `Σ a_i·b_i` — сумма независимых произведений, классическая редукция.

**Технологии.** `parallel for reduction(+ : s)` (п. 5.4.2), распределение `static` по умолчанию.

## 3. Интеграл методом прямоугольников

**Идея.** `y ≈ h · Σ_{i=0}^{N−1} f(x_i)`, `x_i = a + i·h`, `h = (b−a)/N` (формула из задач к гл. 5).
Для `∫₀^π sin x dx = 2` легко проверить точность.

**Технологии.** `parallel for reduction(+ : s)`. `x_i` вычисляется из `i`, а не накапливается
(`x += h`), иначе между итерациями была бы информационная зависимость и цикл нельзя было бы делить.

## 4. Максимум среди минимумов строк матрицы

**Идея.** `y = max_i min_j a_ij` (задача матричных игр). Строки независимы.

**Технологии.** `parallel for reduction(max : res)` по внешнему циклу (строкам); минимум строки —
в приватной переменной, внутренний цикл последовательный (строка читается из памяти подряд).
Матрица хранится одним массивом `a[i*n + j]`.

## 5. Задача 4 для матриц специального вида + правила распределения итераций

**Идея.** Для нижнетреугольной матрицы длина строки растёт от 1 до N — нагрузка итераций
неравномерна (как в примере 5.4 лекции с верхнетреугольной матрицей). Для ленточной (`|i−j| ≤ N/10`)
нагрузка почти равномерна — контрольный случай.

**Технологии.** Параметр `schedule` (п. 5.3.1): `static` (поровну, блоками заранее), `static,1`
(циклически), `dynamic,chunk` (блоки выдаются по мере освобождения потоков), `guided` (блоки
уменьшаются экспоненциально). Для перебора всех правил одной функцией — `schedule(runtime)`:
правило берётся из `omp_set_schedule` (аналог переменной окружения `OMP_SCHEDULE`).

## 6. Режимы schedule на цикле с неравномерной нагрузкой

**Идея.** Итерация `i` «тяжёлая» (генерирует 1000 случайных чисел) с вероятностью `i/n` — к концу
цикла тяжёлых итераций больше. Генератор засевается номером итерации, поэтому нагрузка не зависит
от числа потоков и порядка выполнения.

**Технологии.** `schedule(runtime)` + `omp_set_schedule`: `static`, `static,1`, `static,64`,
`dynamic,1`, `dynamic,64`, `guided,1`, `guided,64`; `reduction(+)`.

## 7. Редукция через разные способы взаимоисключения

**Идея.** Сумма элементов вектора с общим накопителем, защищённым разными механизмами
(п. 5.5), и сравнение с `reduction` (п. 5.4.2).

**Технологии.**
- `#pragma omp atomic` (п. 5.5.1) — неделимая операция, часто аппаратная; самый дешёвый механизм.
- `#pragma omp critical` (п. 5.5.2) — блок, исполняемый одним потоком, через мьютекс.
- Замки `omp_lock_t`: `omp_init_lock / omp_set_lock / omp_unset_lock / omp_destroy_lock` (п. 5.5.3).
- Для каждого механизма два варианта: синхронизация на каждой итерации и «локальная сумма +
  одна синхронизация на поток» (`omp for nowait`).

## 8. Скалярные произведения набора векторов, sections

**Идея.** Пары векторов лежат в бинарном файле (`--gen`). Ввод и вычисление — две раздельные задачи,
выполняемые параллельно: пока считается пара k−1, читается пара k (двойная буферизация).

**Технологии.**
- Распараллеливание по задачам — `#pragma omp sections` / `section` (п. 5.6).
- Одна область `parallel num_threads(2)`, внутри цикл по шагам; на каждом шаге `sections` раздаёт
  двум потокам секцию чтения и секцию вычисления.
- Синхронизация «производитель–потребитель» (п. 5.1.2) — неявный барьер в конце `sections`
  (п. 5.6: «выполнение директивы sections синхронизировано»): после барьера прочитанная пара
  готова, а буфер посчитанной пары свободен.
- Внутри секции вычисления — вложенный `parallel for reduction(+)`, для этого `omp_set_nested(1)`
  (п. 5.7.7).

## 9. Вложенный параллелизм (на задаче 4)

**Идея.** Сравнить распараллеливание циклов разного уровня вложенности: только внешний (по строкам),
только внутренний (минимум в строке), оба уровня одновременно.

**Технологии.**
- Поддержка вложенности (п. 5.7.7): `omp_set_nested(1)` и проверка `omp_get_nested()`
  (печатается в stderr, у GCC — 1, допустимо до 255 активных уровней).
- `parallel for reduction(max)` снаружи и `parallel for reduction(min)` внутри;
  для стандартных конфигураций используются схемы 2 × t/2 и t/2 × 2.
